# IMD6900 Frens: the art, deployed by the IMD swarm

The on-chain art of the 2222 [IMD6900 Frens](https://imd6900.pages.dev) and the renderer that draws them, packed so the
IMD swarm can deploy them with IMD's `evm_contracts` launch: constructors only, static arguments, nothing called after.

- `src/FrenArtChunks.sol`: `FrenArtChunk1..7`, data contracts. Each one's code is a STOP byte (calling it does nothing)
  followed by up to 24,575 bytes of art: 69 layers (13 faces per character, 3 lab coats, 2 hats, 15 items,
  10 backgrounds) and a 256-colour palette, 141.6 KB of decoded art in all. Chunks 4 and 7 frame each group of up to
  32 art bytes with a PUSHn byte so the launch floor's opcode scan accepts the data; the renderer removes this framing.
  Chunks 1 and 2 retain their original bytes and code hashes.
- `src/FrenArtIndex.sol`: where every layer sits (chunk, offset, length), the colour tables, the face table, and each
  chunk's code hash.
- `src/FrenRenderer.sol`: draws a fren from its combo and seed: an 84x84 8-bit bitmap inside an SVG, with its traits,
  as `tokenURI(tokenId, combo, seed)` and `pendingURI(tokenId)`. Its constructor takes the seven chunks and checks each
  one's code hash, so it can only ever draw this art. No owner, nothing to configure, nothing that changes.

Both Solidity files under `src/FrenArt*` are generated by `script/art/chunks.py` from `script/art/data` (the art kit's
export): never edit them by hand. Regenerate offline with `python3 script/art/chunks.py` (uses Foundry's `cast keccak`).
Generation scans every runtime, rejects oversized chunks, and pins the original launch-1 hashes.

## The frens and this art

The frens contract (`IMD6900Frens`, 0x69004fEd3d8a34FFA952d15A128f74D8340fa79d on Ethereum) draws through whatever
renderer its owner points it at, until the owner freezes the art for good (`setRenderer`, `freezeArt`). The frens
launch with a renderer of their own; once this one is deployed and checked on chain, the owner points the frens here.

## Tests

`forge test` (offline, no RPC):
- `test_MatchesTheReference`: bitmaps identical to the art kit's reference renderer (`expected.json`);
- `test_SameAsTheLaunchRenderer`: byte for byte the same `tokenURI`, `pendingURI`, attributes and canvases as the
  renderer the frens launch with (`test/ref/FrenRendererRef.sol`);
- `test_LaunchesFitTransactions`: explicit gas estimates, including runtime code deposit, calldata and allowances for
  constructor execution and factory overhead, stay below 95% of 2^24 gas. Foundry's `gasleft()` around CREATE can omit
  creation costs, so these are estimates, not measured transaction receipts. The deployment service must simulate
  the actual factory transaction against its gas ceiling;
- `test_AllEntriesRetainOriginalBytes`: all 69 decoded layers and the palette match the original art export;
- `test_AllChunksPassFloorAndMatchIndex`: all seven runtimes match the generated sizes/hashes and pass the exact
  launch-floor opcode scan; the renderer passes the scan and runtime size limit too;
- `test/LaunchPart1.t.sol`: CREATE2 deployment of chunks 1 then 2, without arguments or ETH, preserves their pinned
  original hashes; calls are inert and the constructors reject ETH;
- `test_TakesOnlyThisArt`: the renderer refuses other chunks, or these in another order.

`python3 -B -m unittest discover -s script/art` checks the generator's scanner, lossless framing, unchanged passing
chunks and runtime size limits.

## The three launches (`evm_contracts`, Ethereum mainnet)

Ethereum caps a transaction at 2^24 gas and IMD deploys a launch in one, so the art goes in three. None of these
contracts has an owner; `owner` in the request is still the team wallet,
0x35da9c0303507ddf708e87f2568eddf12c47a059.

1. `FrenArtChunk1`, `FrenArtChunk2`: no constructor arguments.
2. `FrenArtChunk3`, `FrenArtChunk4`: no constructor arguments.
3. `FrenArtChunk5`, `FrenArtChunk6`, `FrenArtChunk7`, then `FrenRenderer` with seven address arguments, in order:
   the chunks from launches 1 and 2 (static addresses), then `$contract:FrenArtChunk5`, `$contract:FrenArtChunk6`,
   `$contract:FrenArtChunk7`.

The renderer's constructor reverts unless every chunk is exactly this repository's, so a launch that changed the art
can't produce a working renderer.
